# Policy proposal, 2026-09-18: `vcs.ref.delete` and `harness.launch.*` in one amend

Two lines that were proposed separately on 2026-09-17, combined so the human
runs one `approval policy apply`, one amend and one policy pull request. Three
separate applies would each open a pull request from the same base, and the
second and third would conflict on `APPROVAL.md` and the log.

The reasoning for each line lives in its own page and is not repeated here:

- `docs/proposals/vcs-ref-delete-2026-09.md` (APRV-352): removing a remote
  branch is its own class and asks a human.
- `docs/proposals/harness-launch-2026-09.md` (APRV-354): starting a second agent
  harness resolves only under an explicit rule; this pair is that rule, manual
  for the family and human-only for Muse Code.

The read-scope line (`docs/proposals/read-scope-2026-09.md`, APRV-347) is
deliberately NOT in this page. On this repository it would make every agent
read outside the primary checkout, the scratchpad and the temp root a manual
request, which includes the agent's own plan and memory files under
`~/.claude/`. It wants a `read_scope.roots` decision first and travels on its
own.

Apply with:

```bash
cd /Users/carter/dev/approval-md && approval policy apply docs/proposals/policy-2026-09-18.md
```

Current:

```yaml
  vcs.history.rewrite:       { autonomy: human-only }   # a person rewrites shared history, never an agent (APRV-185)
```
