# approval-md 0.4.5: release notes for downstream

The changelog section `## 0.4.5 — 2026-10-17` in [`CHANGELOG.md`](../../CHANGELOG.md)
is the authoritative statement of this release. It becomes the GitHub Release
body when the tag is published (`scripts/release-notes.mjs`, APRV-396). This
page is the short companion for the downstream projects that pin this runtime.

Until the tag `v0.4.5` exists and the Trusted Publishing run has finished,
`approval-md@0.4.5` is only a version string this source tree carries. The tag
and its push are gated `release.publish` acts. Check the registry
(`npm view approval-md@0.4.5 version`) before baking the string anywhere.

## Why there is no 0.4.4 on npm

0.4.5 carries exactly 0.4.4's content. The tag `v0.4.4` was cut at `5e8db0ea`,
but main had moved on by the time the release workflow verified it. The
publish binding requires the tag, the relay's head, the checked-out commit and
current `origin/main` to be one commit, so it refused the run before anything
reached the registry. [`docs/trusted-publishing-runbook.md`](../trusted-publishing-runbook.md)
says a tag that fails the identity checks is never moved or deleted; the
release takes a new version instead. So:

- `v0.4.4` stays in the repository as a dead tag;
- `approval-md@0.4.4` does not exist on npm, and there is no GitHub Release
  for it;
- [`0.4.4.md`](0.4.4.md) still describes the content correctly. Read every
  `0.4.4` in it as `0.4.5` wherever it names a version to install or pin.

## What changes for a resident and for an operator

Moving up from 0.4.3, everything in [`0.4.4.md`](0.4.4.md) applies:

- `date` in its display forms and the system-information readers are
  `read.shell`;
- the 0.4.3 classifier holes are closed, so some commands that used to pass
  are now refused with a refusal that names the construct;
- `command-class` conformance moves to 1.7.0.

Against the `v0.4.4` tag nothing changes but the version string. Main moved
only in `backlog/` and `metrics/` between that tag and this release, and
neither ships in the package. The string shows in the CLI banner and in the
`approvald 0.4.5` author name on the daemon's evidence commits.

## Upgrade order

1. Publish 0.4.5 and read it back:
   `npm view approval-md@0.4.5 version` and
   `npm view approval-md@0.4.5 dist.integrity`.
2. The control plane pins `APPROVAL_MD_VERSION=0.4.5` and the matching
   `APPROVAL_MD_INTEGRITY`. A pin that names 0.4.4 cannot install.
3. One update per box. The overlay roll that adds per-message timestamps
   does this, so set the pins BEFORE that roll. A box still on 0.4.3 keeps
   refusing `date` and keeps the 0.4.3 holes.
4. Only after every box is on 0.4.5 may the overlay's AGENTS.md tell agents
   to run `date` when unsure.
5. The checkpoint rebake follows later; it is not on the critical path.
