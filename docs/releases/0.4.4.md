# approval-md 0.4.4: release notes for downstream

The changelog section `## 0.4.4 — 2026-10-12` in [`CHANGELOG.md`](../../CHANGELOG.md)
is the authoritative list of changes. It becomes the GitHub Release body when
the tag is published (`scripts/release-notes.mjs`, APRV-396). This page is the
short companion for the downstream projects that pin this runtime. It covers
what 0.4.4 changes for a resident and for an operator, and the order the pins
move in (APRV-503, APRV-504, APRV-508).

Until the tag `v0.4.4` exists and the Trusted Publishing run has finished,
`approval-md@0.4.4` is only a version string this source tree carries. The tag
and its push are gated `release.publish` acts. Check the registry
(`npm view approval-md@0.4.4 version`) before baking the string anywhere.

## What changes for a resident

- **The agent can read the clock.** On 0.4.3, `date` was refused
  `hook-unclassified` and the `python3 -c` fallback was refused `hook-opaque`.
  An agent therefore worked from the "today" line in its prompt, which goes
  stale in a long chat. On 0.4.4, `date` in its display forms is `read.shell`:
  - `date`, `date +FMT`, `date -u +FMT`, `date -d STRING +FMT`;
  - `TZ=Asia/Kolkata date`;
  - the same inside `$(…)` and in pipelines.

  Every setting form (`-s`, `--set`, a bare `MMDDhhmm` operand) and every form
  that opens a file (`-f`, `-r`, a zone path) stays refused.
- **System-information readers.** These commands are `read.shell` in their
  display forms:
  - `uptime` and `whoami`;
  - `hostname` with no flag or one display flag;
  - `df` and `free` with display flags only;
  - `seq` with at most 100,000 values;
  - `paste` on files, scoped like `cat`.

  `[` is read the same way `test` is. `hostname NAME` sets the host name and
  stays refused.
- **Some commands that used to pass are now refused.** These were holes; see
  "Holes in 0.4.3" in the changelog:
  - a `$(…)` in a redirection target;
  - `>&WORD` onto a file, which is now a write;
  - a `$(…)` in an unquoted heredoc body;
  - a `$` in a heredoc delimiter;
  - a bare `PATH=`, `TZ=`, `HOME=` or `LD_*=` assignment in its own segment,
    and `printf -v PATH`;
  - `test -v 'a[…]'`;
  - `[ $(…) … ]` with the substitution unquoted. Quote it: `[ "$(date +%u)" -gt 5 ]`.

  An agent that hits one of these gets a refusal that names the construct.

## What changes for an operator

- **Classifier rows.** These rows answer `read.shell`:
  - `date-read`;
  - `sysinfo-read` (uptime, whoami);
  - `hostname-read`, `df-read`, `free-read`, `seq-read`;
  - `paste-read`;
  - `[` in `read-shell`.

  Each row is an exact-spelling allow-grammar, checked against GNU coreutils
  and uutils 0.10 (`tests/command-class-differential.test.ts`). The lexer is
  checked against a real bash (`tests/command-class-shell-differential.test.ts`).
  The docs tables in `docs/claude-code-hook.md` list every accepted spelling.
- **Policy.** No new key and no schema change. Every new answer is a class or
  refusal that already existed. A policy that holds `read.shell` autonomous
  (the Agent Village template does) now lets the display forms above run
  unattended.
- **Conformance.** `command-class` moves through 1.6.0 (APRV-503) to 1.7.0
  (APRV-508). Both are minor bumps that add new inputs only.

## Upgrade order

1. Publish 0.4.4 and read it back:
   `npm view approval-md@0.4.4 version` and
   `npm view approval-md@0.4.4 dist.integrity`.
2. The control plane pins `APPROVAL_MD_VERSION=0.4.4` and the matching
   `APPROVAL_MD_INTEGRITY`.
3. One update per box. The overlay roll that adds per-message timestamps
   does this, so set the pins BEFORE that roll. A box still on 0.4.3 keeps
   refusing `date` and keeps the 0.4.3 holes.
4. Only after every box is on 0.4.4 may the overlay's AGENTS.md tell agents
   to run `date` when unsure.
5. The checkpoint rebake follows later; it is not on the critical path.
