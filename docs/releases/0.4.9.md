# approval-md 0.4.9: release notes for downstream

The changelog section `## 0.4.9 — 2026-11-25` in [`CHANGELOG.md`](../../CHANGELOG.md)
is the authoritative list of changes. It becomes the GitHub Release body when
the tag is published (`scripts/release-notes.mjs`, APRV-396). This page is the
short companion for the downstream projects that pin this runtime. It covers
what 0.4.9 changes for a box operator and for a resident, and the order the
pins move in (APRV-518, APRV-537, GLOB-WRITE; #695).

Until the tag `v0.4.9` exists and the Trusted Publishing run has finished,
`approval-md@0.4.9` is only a version string this source tree carries. The tag
and its push are gated `release.publish` acts. Check the registry
(`npm view approval-md@0.4.9 version`) before baking the string anywhere.

## What a box operator gets

- **Writes to guarded paths are judged where they land.** On 0.4.8 a number
  of command lines wrote the policy file, the approval home, a harness's own
  hook registration or a credential while the hook read them as ordinary
  workspace writes: a glob or a `${X:-…}` default in the write target
  (`echo x > ~/.hermes/[!Z]uth.json`), a guarded name in another letter case
  or Unicode fold (`echo x > Approval.MD`), zsh's `>!` forms, a write into
  `.git` or a `git remote` change that arms a later push, `rm -rf` of an
  organ directory or of a parent of one, and a second protected path on the
  same line. Each now takes the guarded path's class, and in most cases the
  class 0.4.8 gave rides beside it, so the strictest decision under the box's
  policy answers. This is every harness's hook, the Hermes hook included.
- **A copy into a credential path is a write, and behind a wrapper a target
  the shell builds fails closed (#706).** On 0.4.8 `cp README.md
  .approval/env` answered `account.credential` alone; the destination is now
  a write, so `policy.core` answers first with the credential class beside
  it, and a copy whose arguments the hook cannot read adds that class too.
  Behind a wrapper (`command`, `env`, `nice`, `sudo` and the like), a
  variable, a command substitution, a glob, a brace or a `~user` in the line
  reports `policy.core` (`copy-target-unknown`) beside the credential class,
  as plain `cp .approval/env $X` does; a secret-named variable counts too
  (`command cp $APPROVAL_TG_TOKEN notes.txt`). Under the policy `approval
  init` writes both classes are manual and no decision moves; a policy that
  runs `account.credential` more lightly than `policy.core` now waits on
  `policy.core` for these lines. A credential read spelled as a glob by a
  program that only reads (`less ~/.hermes/profiles/*/auth.json`) is still
  the read.
- **A guarded name spelled in a dollar quote, or with a parameter spliced
  into it, is judged as the guarded path (#709).** `echo x >>
  $'\x41PPROVAL.md'` writes the policy file in bash and zsh, and `echo x >
  APPROVAL$E.md` writes it when `E` is empty; both were ordinary workspace
  writes, and `cat $".approval/env"` and `cat .approval/$F` were plain reads.
  The hook now decodes `$'…'` where bash and zsh decode alike, and reads a
  word with a part it cannot read (a parameter, a substitution's output, an
  escape the shells read differently) against every guarded path and `.git`:
  a possible match takes that path's class with the earlier answer beside it,
  and a credential read takes `account.credential`. A word whose directory is
  wholly unread asks only where a guarded file's name ends it
  (`$D/APPROVAL.md` asks; `$OUT` and `$D/$F` keep their answer). On one day's
  19,368 Bash calls holding a `$`, 11 answers moved, each stricter; 8 of them
  are writes below a `$W/scripts` directory, which now take `cron.manage`
  beside (`W` may be the Hermes home).
- **A credential read through a negated glob bracket is the credential read,
  and the hook matches globs in linear time (#682).** The hook read `[!x]` and
  `[^x]` as the literal members `!`, `^` and `x`, so
  `cat ~/.hermes/[!x]uth.json` was a workspace read while bash and zsh open
  `auth.json`; `[!...]` is now negated as every shell negates it, and the line
  takes `account.credential`. The credential pass matched glob paths with a
  backtracking regex: on 0.4.8 a `cat` of a path with 160 `*` took 15.2 s,
  and a longer run passes the harness's 60 s hook timeout, after which the
  call ran ungated. Every hook caller now walks the pattern with no
  backtracking. The hook also reads a line as the shell joins its
  `\`+newline continuations, and
  every command as zsh reads it with `extendedglob` and `braceccl` on (a
  user's zshrc may set either), the stricter answer standing. A write-target
  glob takes every class among the guarded paths it could match, each judged
  by the policy (`echo x > A*.md` is `policy.core` and `policy.edit`), and one
  past a cap (4,096 brace candidates, 32 segments, two million matcher steps)
  is judged unknown: `log.mutate`, `policy.core` and the class of every
  guarded name it could match.
- **`files.write.guarded` applies to every policy, at `manual` or stricter.**
  A write landing in `~/.ssh`, a shell start file, a launch agent, `/etc`, a
  PATH folder such as `~/.local/bin`, a credential store such as `~/.aws`, a
  git hooks folder, a Claude Code hooks folder or another user's home now
  needs a person, whatever the policy says; a policy row that sets the class
  lower fails to load (`class-minimum`). The resident template needs no edit
  for this.
- **`write_scope` is opt-in, and not for the template yet.** With
  `write_scope.roots` (or a `files.write.out_of_scope` row), a write landing
  outside the gate root, the session scratchpad, the temp roots and the listed
  roots takes `files.write.out_of_scope`. A core older than 0.4.9 refuses the
  `write_scope` key and fails the whole policy closed, so no template gains it
  while any box runs an older core. `approval doctor` has a `write-scope` row.
- **The hook has a deadline of its own.** Reading a call stops at 15 s, or the
  harness cap less two seconds when that is shorter (Hermes's 30 s default
  leaves the whole 15 s). A call the hook cannot read in time is blocked
  `hook-deadline`, with nothing registered or requested, instead of running
  ungated after the harness kills a slow hook. An ordinary call is read in
  milliseconds.
- **Known in 0.4.9: a `cp` with many `-t` landings is slow through the
  hook.** Since #695 every landing is judged, under every policy, and the
  work grows with the square of their number: a `cp` line of about 8 KiB of
  arguments takes several seconds, and a longer one can meet the 15 s
  deadline and be blocked `hook-deadline`. It fails closed: no such line is
  answered more loosely than before. A fix (#711) is planned for 0.4.10.
- **`approval propose --irreversible` (APRV-537).** A plugin can say the action
  it proposes cannot be undone; the key then resolves `manual` under
  `autonomous`, `supervised-retro` and `supervised-live`, and the person gets a
  card. A core older than 0.4.9 refuses the flag (CLI usage error, `approval
  serve` 403), so a plugin that sends it needs a fallback until every box runs
  0.4.9. **Do not roll a box back past 0.4.9 while a key the flag floored is
  open:** an older core ignores the floor at `start`.
- **Which shipped overlay calls move.** The release PR's class-diff (the
  `overlay-recipes` job, baseline npm 0.4.8, every recipe and `tools:` line
  run through each core's own `approval hook hermes` in a box layout) lists
  every call whose class, decision or card style moves, read at the release
  PR's exact head; the release PR's description names each one and the PR
  that moved it. Read it before the canary box.
- **Release checks for the overlay.** `overlay-recipes-check.mjs` gains the
  CLASS-DIFF gate (`--diff <baseline core>`, B-167) and the NEW-CALLS check
  (`--expected`, `--tag-corpus`, B-167N), which reads `irreversible: true` on
  an expected propose. Their baseline, `BASELINE_CORE`, stays 0.4.8 in this
  release and moves to 0.4.9 after the roll.
- **Conformance.** `command-class` is 2.0.0 (1.9.0 in 0.4.8): seventy-eight
  new vectors, and three released ones move to the stricter answer (#686),
  which makes it a major. `policy-resolution` is 5.1.0 (from 5.0.0): six new
  vectors for the guarded class's built-in minimum. `refusal-unions` is
  32.0.0 (from 31.0.0): `hook_deny_codes` gains `hook-deadline`. `SPEC.md`
  and `APPROVAL.md` are unchanged since 0.4.8.

## What changes for a resident

- **Some lines an agent ran alone may now come to you as a card.** A write
  landing in `~/.ssh`, a shell start file, a PATH folder or a credential store
  always asks a person. A write into the approval files or a harness's
  settings by another spelling (a glob, another letter case, a dollar quote, a
  spliced parameter), a `git remote` change or a write into `.git` takes the
  class the plain spelling had, and asks where the box's policy asks for that
  class. So does a credential read spelled through a glob
  (`cat ~/.hermes/[!x]uth.json`).
- **An agent can mark a proposal as one that cannot be undone,** and then you
  decide it, under every setting short of human-only. No plugin sends the flag
  until the overlay change that lands it.

## Upgrade order

1. Publish 0.4.9 and read it back:
   `npm view approval-md@0.4.9 version` and
   `npm view approval-md@0.4.9 dist.integrity`.
2. The control plane pins `APPROVAL_MD_VERSION=0.4.9` and the matching
   `APPROVAL_MD_INTEGRITY`, and its CI adds the `0.4.9` line to `CORE_PINS`
   (`test.yml` and `nightly.yml`, held equal by a test). The overlay's
   `APPROVAL_MD_PINNED` and its `expected.json` move with it; the NEW-CALLS
   check runs there, against 0.4.9.
3. One canary box first, then the rest, one update per box.
4. After the roll: `BASELINE_CORE` in this repository's `ci.yml` moves to
   0.4.9. Only then may a template carry `write_scope`, or a plugin propose
   with `--irreversible` and no fallback.

## SPEC.md

The release commit does not edit `SPEC.md` and proposes no new amendment.
Nothing merged since 0.4.8 edits it. `write_scope` is described in
`schema/policy.schema.json` as a proposed §5.2 addition; SPEC.md does not
carry it or `files.write.guarded` yet. `approval propose --irreversible` engages
§7's existing irreversibility floor. The amendments 0.4.6 listed as pending
sign-off stay as 0.4.8 left them.
