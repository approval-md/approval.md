# approval-md 0.4.7: release notes for downstream

The changelog section `## 0.4.7 — 2026-10-21` in [`CHANGELOG.md`](../../CHANGELOG.md)
is the authoritative list of changes. It becomes the GitHub Release body when
the tag is published (`scripts/release-notes.mjs`, APRV-396). This page is the
short companion for the downstream projects that pin this runtime. It covers
what 0.4.7 changes for a box operator and for a resident, and the order the
pins move in (EDGEOS-BLOCK: APRV-533 and the 0.4.7 remedy line and corpus
check; study mode: APRV-527, APRV-528; site: APRV-529).

Until the tag `v0.4.7` exists and the Trusted Publishing run has finished,
`approval-md@0.4.7` is only a version string this source tree carries. The tag
and its push are gated `release.publish` acts. Check the registry
(`npm view approval-md@0.4.7 version`) before baking the string anywhere.

## What a box operator gets

- **EdgeOS recipes run again at the Hermes home (APRV-533).** A resident box
  runs its terminal in `$HERMES_HOME`, which holds credential material. 0.4.6
  read curl's `-H`/`--header` and `--url` values, and wget's `--header`, as
  reads of that directory, so every `skills/edgeos` recipe took
  `account.credential` there, which the village template reserves to humans
  (exit 2). curl opens a file for those options only as `-H @FILE` and
  `--url @FILE`, so 0.4.7 skips a value that opens with neither `@` nor a
  character the shell may still expand. `-H @.env`, `-H "$X"`, `--url @.env`,
  `--url "$U"`, `-K`, `-d`/`--data*`, `-F`, `-T`, `-o`, cookies, certificates,
  `--netrc-file` and every word after `--` are judged as before, and wget's
  `@`- or `$`-first `--header` values stay credential reads.
- **Every verdict that moved, moved from `account.credential` to the class the
  command had without it.** Over 2,376 commands (every literal in the
  command-class and hook tests, the overlay's 63 shipped recipes and the
  incident's vectors), classified at the Hermes home and at `$HOME`, 25
  changed, all curl or wget, and nothing moved stricter. 24 are at the Hermes
  home; all 14 `skills/edgeos` curl recipes in the corpus are `network.call`
  there now. The one `$HOME` row is `curl -H 'Accept: */*' https://e/x`,
  whose header 0.4.6 read as a glob.
- **The `fetch-output-unknown` refusal names its remedy.** The rule is
  unchanged: a curl or wget word that starts with `$` in an option slot is
  `policy.core`. When it fires for that cause, the human-only refusal now ends
  with one fixed line telling the agent to pass the URL as the value of
  `--url` (`curl --url "$VAR/..."`) and to use `curl --url` in place of wget.
  The class, the rule, the refusal code and every other cause's text are byte
  for byte 0.4.6's.
- **A consumer-corpus release check.** The CI job `overlay recipes (consumer
  corpus)` runs a pinned snapshot of every shell recipe the overlay
  (Edge-City/agentvillage) ships to agents through this core's classifier,
  and fails when one resolves to a human-only class under the overlay's
  template, unless `scripts/overlay-recipes/allowlist.json` lists it with a
  reason. The `ci` aggregator requires it, so a tag is cut only from a main
  this check has passed on.
- **Study mode is off unless the operator switches it on** (APRV-527,
  APRV-528). Both study features need `APPROVAL_STUDY_MODE=1` in the process
  environment; a policy cannot set it. With it off, nothing below exists.
  With it on: `approval study withdraw` lets a hosted study operator deny one
  still-pending request (never grant, alter or reopen one), recorded as a
  reject under `human:study-team` on channel `study` with a pseudonymous
  operator id and a replay key; and the Telegram card carries a "Looks wrong"
  button, an ordinary reject flagged `looks_wrong`. The verb is human-only and
  is not published by `approval serve` or the MCP server. No enforcement path
  reads the study record.
- **Conformance.** `refusal-unions` and `schema-validation` carry the study
  record's new vectors (`study_withdraw_refusal_codes` and
  `study-reason-not-channel`). No existing vector expectation moved.

## What changes for a resident

- **EdgeOS works again on their agent.** Event lookups and RSVPs that were
  refused since the 19 October rolls (Hermes reported `plugin_block`) are
  `network.call` again, and the village template's `network.call` rule
  decides them, as it did before 0.4.6.
- **The approval card is unchanged.** With study mode off (every box today),
  the card shows no new row and no new button, and every decision, button,
  grouping, pacing and retry is 0.4.6's.

## Upgrade order

1. Publish 0.4.7 and read it back:
   `npm view approval-md@0.4.7 version` and
   `npm view approval-md@0.4.7 dist.integrity`.
2. The control plane pins `APPROVAL_MD_VERSION=0.4.7` and the matching
   `APPROVAL_MD_INTEGRITY`.
3. One canary box first, then the rest, one update per box. A box still on
   0.4.6 keeps EDGEOS-BLOCK: its EdgeOS recipes stay refused at the Hermes
   home.
4. `APPROVAL_STUDY_MODE=1` is set on a box only when a study run starts there.
   Nothing in this release requires it.
5. The checkpoint rebake follows later; it is not on the critical path.

## SPEC.md

The release commit does not edit `SPEC.md` and proposes no new amendment. The
study record (§8) and its §11.2 registry rows (`study_withdraw_refusal_codes`,
`study-reason-not-channel`) landed with APRV-527 and APRV-528, and the file at
those bytes is attested (seq 84050). The amendments 0.4.6 listed as pending
sign-off stay pending: §5.2, §7 and §11.2 for `exec.code` (APRV-510), and
§5.2's organ list (APRV-511).
