# approval-md 0.4.0: release notes for downstream

The changelog section `## 0.4.0 — 2026-10-04` in [`CHANGELOG.md`](../../CHANGELOG.md)
is the authoritative list of changes and becomes the GitHub Release body when
the tag is published (`scripts/release-notes.mjs`, APRV-396). This page is the
companion for the two downstream projects that pin this runtime: what 0.4.0
gives Agent Village, which pins move, and the state of the conformance vectors

tag and its push are gated `release.publish` acts, so check the registry
(`npm view approval-md@0.4.0 version`) before baking the string anywhere.

## What 0.4.0 gives Agent Village

**The live gate verbs.** A Hermes tenant runs in a sandbox with no local log,
so everything it does reaches the gate through `approval serve` (APRV-421):

- `approval propose --class <c> --key <k> --summary <s> --payload-json <json>`
  declares and asks in one call, with the payload inline. Only a class the
  attested policy marks `agent_may_request: true` (on itself or on a declared
  `<prefix>.*` family) can be proposed; anything else refuses
  `class-not-agent-requestable` and registers nothing. A retry with the same
  bytes appends nothing.
- `approval start <task> --action <k> --payload-json <json>` records the
  `execution.started` for a proposed action its requester carries out, bound to
  the proposed bytes. On the policy path it refuses `not-granted` wherever a
  human said no or a live draw selected the bytes.
- `approval wait --timeout 0` reads the current state and never sleeps, so a
  poller through `serve` holds nothing. `wait` answers `void` (exit 7, ask
  again) for a request pinned to a re-attested policy, `expired` (exit 3) for a
  lapsed grant, and refuses `not-registered` (exit 1) for a task the log never
  registered (APRV-428).
- `approval serve --listen unix:<path>` (or `APPROVAL_SERVE_LISTEN`) opens a
  unix-domain socket in a directory the serving uid owns. Hook calls run on a
  bounded pool of worker threads, so one hook waiting on a human no longer
  stalls `/status`, `/log/follow`, `/export` or the agent's other verbs
  (APRV-427). The agent credential's allowlist is `instructions`,
  `hook_classify`, `request`, `wait`, `withdraw`, `propose` and `start`.
- `approval hook hermes` classifies the Hermes tools it used to wave through
  (`cron.manage`, `process.write`, `browser.exec`, `skill.manage`,
  `agent.delegate`, `message.send`), scopes its organ rules to the home's own
  directories so a hosted `HERMES_HOME` works, and answers every error path
  with the block directive at exit 2. Pair it with Hermes's per-entry
  `fail_closed: true`, on a Hermes build at or past the floor `approval doctor`
  checks.

**The recorder.** `examples/agent-village/approval-policy.md` is the day-one
tenant policy (APRV-446): an autonomous default that records every action, the
three gate organs human-only, the Hermes tool classes and `network.call` /
`read.web` recorded and never gated, `intent.publish.inferred.index` manual and
agent-requestable, and a 72 h proposal window. Every harness start now carries
`policy_sha256`, the attested policy it ran under (APRV-447), and every record
`serve` or the Telegram webhook appends carries the `daemon` id, held to the
policy's `daemons` list (APRV-383, APRV-448). Each append and each stored
payload is fsynced before the verb reports ok, so a platform kill after an
acknowledged record no longer leaves a NUL-filled tail or a missing payload
(APRV-440, APRV-457). An operator gives a shell-less tenant its first policy
with `approval policy attest --bootstrap --as human:<operator>`, once, and the
tenant sees who set it (APRV-449; `docs/hosted-provisioning.md`).

**The relay.** `approval channel relay` (APRV-455) is a loopback listener the
control plane posts human gestures to (`propose`, `attest` or `decline` a
policy; `grant` or `reject` a request), authenticated by
`APPROVAL_RELAY_SECRET` and replay-proof across restarts. Each gesture names an
EdgeOS sender that must map to an approver under the policy in force
(`approvers.<id>.senders.edgeos`), so the relay never decides as an identity of
its own. A refused Telegram tap now re-offers the live prompt on a fresh card
(APRV-442), and `approval channel telegram webhook` (APRV-424) receives taps
without a long-poll process.

`approval serve` runs no channel and takes no `--api-base`: a launcher still
runs `approval up --api-base` (or the relay) beside it, as
`docs/hermes-hook.md` "For Agent Village" describes.
