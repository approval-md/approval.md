# approval-md 0.4.6: release notes for downstream

The changelog section `## 0.4.6 — 2026-10-18` in [`CHANGELOG.md`](../../CHANGELOG.md)
is the authoritative list of changes. It becomes the GitHub Release body when
the tag is published (`scripts/release-notes.mjs`, APRV-396). This page is the
short companion for the downstream projects that pin this runtime. It covers
what 0.4.6 changes for a box operator and for a resident, and the order the
pins move in (APRV-510, APRV-511, APRV-517, APRV-520 to APRV-525).

Until the tag `v0.4.6` exists and the Trusted Publishing run has finished,
`approval-md@0.4.6` is only a version string this source tree carries. The tag
and its push are gated `release.publish` acts. Check the registry
(`npm view approval-md@0.4.6 version`) before baking the string anywhere.

## What a box operator gets

- **The 0.4.5 classifier holes are closed.** Each one let a command run below
  the class it should have had; see "Holes in 0.4.5" in the changelog:
  - a `git push` whose delete flag was bundled or abbreviated (`-ud`,
    `--del`) was a plain push, so `vcs.ref.delete` was never asked (APRV-517);
  - a git global option that takes a value made its value the subcommand, so
    `git -C status push --force origin main` was `read.shell` (APRV-520);
  - an environment assignment in front of git hid the program git runs, so
    `GIT_PAGER=<cmd> git log` ran `<cmd>` as `read.shell` (APRV-521);
  - six classes of spelling read a credential file below
    `account.credential`, git's reading verbs among them (APRV-522);
  - an assignment-shaped word with a quoted or escaped name was read past, so
    the classifier judged a different program from the one bash runs
    (APRV-523);
  - a write into `$HERMES_HOME/hermes-agent/`, `$HERMES_HOME/plugins/` or onto
    `$HERMES_HOME/.op.env` was `files.write.workspace`, autonomous under the
    village template (APRV-511).
- **The credential-read and command-word closes are on every adapter.** A
  credential file is `account.credential` however the read is spelled: through
  git's reading verbs, `..`, `.`, `//` or a case change, an earlier `cd`, a
  symlink, a glob or brace list, `$HOME` or `$HERMES_HOME`, inside `$(…)`, in a
  reader's own option, or behind a `<` (APRV-522). A read whose last path
  component is a command substitution is judged the same way on every adapter,
  as it already was on Hermes (APRV-524). Where the hook cannot know where a
  read lands, the read is `account.credential` (fail closed). The word bash
  runs is the word the classifier judges: git with an assignment in front of it
  is refused unless every assignment is on a closed no-op list (APRV-521), and
  a quoted or escaped assignment name makes the word the program (APRV-523).
  No credential location was added.
- **The Hermes home's other organs are `policy.core`** (APRV-511). Writes into
  `hermes-agent/` and `plugins/`, onto `.op.env`, and the `hermes` verbs that
  rewrite an organ (`plugins install|update|remove|enable|disable`,
  `config set|unset|edit|migrate`, `hooks revoke`, `update`, `uninstall`) are
  `policy.core`, which the village template holds human-only. A read of
  `.op.env` or `hermes-agent/.env` is `account.credential`. Reads of the
  runtime's source keep their class.
- **Some commands that used to pass are now refused or go to a person.** Every
  verdict that moved, moved stricter. The changelog names each cost; the ones
  an agent is most likely to meet:
  - `FOO=1 git …` and any other assignment off the list, `n+=1` and array
    writes;
  - `git --git-dir=.git status` and the other `=`-joined git globals; use `cd`;
  - `git push origin $BRANCH`; write the ref name out;
  - `cp "$f" bak/`, `mv $tmp out`, `curl "$URL"`; put `--` before the operand
    (`cp -- "$f" bak/`, `curl -- "$URL"`) to keep the class;
  - under the Hermes hook, a write whose directory an unexpandable variable
    decides (`mkdir -p "$OUT"`, `> "$TMPDIR/x"`);
  - a `grep`, `rg` or `find` operand holding `$`, and relative reads after a
    `cd` the hook cannot resolve.

  An agent that hits one of these gets a refusal.
- **`exec.code` is opt-in and off by default** (APRV-510). A policy that never
  names `exec.code` keeps every refusal byte for byte, and nothing new blocks
  an agent's code runs. `python3 -c`, `node -e`, `deno eval` and kin, an
  interpreter running a file that is not a skill script, and Hermes
  `execute_code` stay refused before policy unless the operator opts in.
  Opting in takes a policy block: `exec.code.custody: attested` (the
  operator's statement that credential custody is in place) opens the shell
  forms, and `exec.code.execute_code: hooked` beside it opens Hermes
  `execute_code`. A record binds the program's SHA-256 and length, never its
  text. `bash -c`, `sh -c`, `eval`, a pipe into an interpreter, stdin and a
  program inside a subshell stay refused, and Codex stays closed. A core older
  than 0.4.6 refuses the `exec` key and fails the whole policy closed, so add
  the block only after every core that reads the policy runs 0.4.6.
- **A Hermes record carries its harness version** (APRV-419), so
  `approval doctor` can compare it.
- **Conformance.** `command-class` moves from 0.4.5's 1.7.0 through 1.8.0
  (APRV-517) to 1.9.0 (APRV-511); no existing vector expectation moved. New
  suite `hook-exec-code` 1.0.0; `refusal-unions` 29.0.0; `schema-validation`
  3.4.0.

## What changes for a resident

The Telegram reminder copy is in plain words (#655, P-9, APRV-525):

- **A restart sends one reminder, in plain words.** When a listener starts and
  re-sends pending requests, the message in front of them reads
  `Reminder: N requests are still waiting for you.` and then either
  `They are repeated below; buttons on older messages above still work, and
  nothing is answered twice.` or, behind a relay where older buttons do not
  work, `Use the buttons below; buttons on older messages above no longer
  work.` When stale requests are grouped, the stale summary opens with that
  count and says the same about older buttons, and the separate banner is
  skipped, so the resident gets one reminder instead of two.
- **The summary, the digest and `/queue` name each request by what the agent
  said and how old it is,** under "What your agent says (not checked)". They
  no longer show action keys, task ids, class tallies, grouping keys, or text
  about hooks, retry grace and log events. `/queue`'s header names the oldest
  request correctly when the list is shown newest first.
- **The request card's headings read** "Checked by approval.md", "Exactly what
  you are approving" and "What your agent says (not checked)".

Unchanged: the card's action-key row and its canonical payload block (which
`display_hash` binds, SPEC.md §10.3), decisions, buttons, grouping, pacing and
retries.

## Upgrade order

1. Publish 0.4.6 and read it back:
   `npm view approval-md@0.4.6 version` and
   `npm view approval-md@0.4.6 dist.integrity`.
2. The control plane pins `APPROVAL_MD_VERSION=0.4.6` and the matching
   `APPROVAL_MD_INTEGRITY`.
3. One update per box. A box still on 0.4.5 keeps the 0.4.5 holes and the old
   Telegram copy.
4. Only after every box that reads a policy is on 0.4.6 may that policy carry
   an `exec` block. Nothing requires one: without it, `exec.code` stays closed.
5. The checkpoint rebake follows later; it is not on the critical path.

amendments the changes above already made stay pending sign-off: §5.2, §7 and
§11.2 for `exec.code` (APRV-510), and §5.2's organ list (APRV-511).
