# approval-md 0.4.3: release notes for downstream

The changelog section `## 0.4.3 — 2026-10-07` in [`CHANGELOG.md`](../../CHANGELOG.md)
is the authoritative list of changes and becomes the GitHub Release body when
the tag is published (`scripts/release-notes.mjs`, APRV-396). This page is the
short companion for the downstream projects that pin this runtime: what 0.4.3
changes for a resident and an operator, and the order the pins move in
(APRV-502).

Until the tag `v0.4.3` exists and the Trusted Publishing run has finished,
`approval-md@0.4.3` is a version this source tree carries and nothing more. The
tag and its push are gated `release.publish` acts, so check the registry
(`npm view approval-md@0.4.3 version`) before baking the string anywhere.

## What changes for a resident

- **Skill scripts run under enforcement.** On 0.4.2 with `APPROVALD_ENFORCE=1`,
  every skill script the overlay's AGENTS.md routes through `terminal` was
  denied `hook-unclassified`: the name gate (`bun
  skills/agent-profile/scripts/profile.ts`), the welcome (`bun
  skills/index-network/scripts/welcome.ts`), `agent-commons` search, the token
  audit and the selfie script. Residents got the fallback welcome and the
  default name. On 0.4.3 an interpreter (`bun`, `node`, `python3`, `python`)
  running `skills/<skill>/scripts/<file>` is `exec.local`. Curl recipes, MCP
  and plugin tools, and cron jobs were never affected.

## What changes for an operator

- **Two classifier rules, one class that already existed.** `skill-script`
  (bun, python, python3) and `node-skill-script` (node) emit `exec.local`
  (SPEC §7, "scripts inside the workspace"). The shape is exact: relative
  `skills/<skill>/scripts/<file>`, or an absolute path ending
  `.hermes[/profiles/<p>]/skills/<skill>/scripts/<file>`, with only allowlisted
  inert flags before the script. Everything else keeps its 0.4.2 answer.
  `docs/hermes-hook.md` has the full list of what stays refused.
- **Policy.** No new key and no schema change. A policy with no `exec.local`
  line resolves it by `defaults.autonomy`. If the resident template's defaults
  are `manual`, these calls go to the phone until the template carries
  `exec.local: autonomous` (SPEC §7's default gravity for the class). That is a
  policy edit and a human attestation, outside this release.
- **The disk check and its limit.** The hook resolves the script from the
  call's `workdir` and refuses a symlink out of its `skills/<skill>/scripts/`
  directory; a real path on an organ or a credential file takes that class.
  Under co-location the daemon (`approvald`) cannot read the resident's 0700
  Hermes home, so that check cannot look on a hosted box and the text check
  stands alone. That is deliberate: refusing on EACCES would deny every skill
  script fleet-wide.

## Upgrade order

1. Publish 0.4.3 and read it back (`npm view approval-md@0.4.3 version`).
2. The control plane pins `APPROVAL_MD_VERSION=0.4.3` and the matching
   `APPROVAL_MD_INTEGRITY`.
3. One update per box. A box still on 0.4.2 keeps denying skill scripts as it
   does today; nothing else differs between the two.
4. The checkpoint rebake follows later; it is not on the critical path.

Nothing in a policy has to change before the pins move.

## Conformance and SPEC.md

No conformance suite version moved and no refusal code was added. The release
does not edit `SPEC.md` and proposes no amendment: `exec.local` is already a
§7 class.
