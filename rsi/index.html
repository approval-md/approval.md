Human approval for agent actions, demonstrated live at the RSI Harnesses hack.

One agent, one gate, one phone. Everything below is read straight out of an append-only, hash-chained log you can verify yourself.

What you are watching

An agent is running with a harness that gives it exactly one path to the real world: a request into an approval gate, and a human decision coming back. It has no email client, no shell, no card on file. When it wants a side effect it registers the action, the runtime classifies it against a policy file, and anything marked manual stops dead until a person says yes from their phone. Execution then runs against a single-use token that names that one action.

Every step of that is a record in an append-only log, each entry hashed onto the one before it. Nothing is claimed here that the chain cannot show, which is why the verify badge below turns green only when the whole log recomputes clean.

  1. A benign task runs untouched. Reads and local work are autonomous. The gate is a filter, and a filter that stops everything teaches an agent nothing.
  2. A side-effecting run waits, and is approved from a phone. The request lands in the queue with its class, cost and TTL. The token is minted only after a human taps approve.
  3. The agent asks to loosen its own policy, and is refused. Policy edits are themselves a gated class. Self-modification gets the same scrutiny as spending money, and the refusal lands in the log as its own record.
  4. A real email goes out inside the granted window. One approval, one action, one token, and a TTL that expires. The irreversible thing happens because a person chose it, seconds earlier, on the record.
