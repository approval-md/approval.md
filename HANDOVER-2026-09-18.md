## 5. Muse Code, the short version

Carter wants first-class Muse support and ruled (2026-09-18) that it ships as
an **ordinary adapter**, fail-open caveat stated first, not refuse-early.
Live probe of `muse-bin-1.3.0-R3233.1`:

- Reads `.muse/hooks.json`, Claude-style event-keyed object. Envelope is
  snake_case. Tools: `bash` (with per-call `workdir`), `write_file` (path
  relative to top-level `cwd`), `read_file`, `search`, and a bookkeeping tool
  `submit_reminder_decision` that is most of the traffic and must pass through.
- Post-events carry a real outcome (`exit_code`, `terminal_status`) and accept
  no verdict.
- **Blocks** on exactly three refusal forms: nested
  `hookSpecificOutput.permissionDecision: "deny"` at exit 0, `{"decision":"block"}`
  at exit 0, or no stdout with exit 2. **Any mixed or unsupported key
  invalidates the output and fails open, even at exit 2.** Crash, 30 s timeout
  and garbage all fail open.
- After a deny the agent retries within seconds and, once, read the probe's
  state file to see what had stopped it. When a terminal command was pasted
  into it by mistake it read a file under `~/dev/approval-md` and ran the
  command: no workspace confinement in `permission_mode: default`.
- **Hard rule from Carter: Muse never runs with a Contributor model
  (`*-contributor` ids train on prompts and completions), and no agent ever
  runs `muse`.** Launch with `muse --model muse-spark-1.3`, only in a scratch
  directory, until the adapter, the read-scope line and his own confirmation
  are in place. `harness.launch.muse` is human-only in the policy proposal.
- Before anything is published at approval.md/muse: rerun the trials through
  the real adapter and stage the out-of-folder read deliberately
  (`private/muse-analysis-2026-09-18.md`, section 10).

## 6. Working rules learned in these two pushes

Add these to the list in the 09-16 handover.

- **Merge main and rebuild immediately before arming.** #414 compiled alone
  and broke in the merge group because another lane had made `readTools`
  required.
- **Confirm the queue by GraphQL** (`isInMergeQueue`), and read
  `RemovedFromMergeQueueEvent` when a PR lingers. "Already queued to merge"
  was stale twice. `autoMergeRequest: null` with `isInMergeQueue: true` means
  the arm took effect.
- **A protected-path edit needs a records advance before the guard can
  pass**, and the guard reads an open records branch, so the records PR need
  not merge first. Lanes message the orchestrator the moment such a commit is
  pushed; the orchestrator runs `cd /Users/carter/dev/approval-md && approval log advance --pr`.
  Do not pass `eval "$(approval env)"` through the hook: it refuses the
  substitution, and the verb works without it.
- **Do not advance while a records PR is in the merge queue**: the branch
  cannot be updated, the verb opens a `-2`/`-3` branch, and that duplicate
  conflicts as soon as the first merges. Wait, then advance, or close the
  duplicate with a note and re-advance.
- **SPEC.md edits: few, and never an edit to your own earlier SPEC edit.**
  Two commits are fine (#432 replayed three records across two). Many edits
  over several rounds on a 200 KB file hit the guard's replay byte limit
  (#427) and cost a human sign-off. If a sign-off is needed and main is about
  to move, freeze the branch, let main settle, merge, refreeze, and only then
  hand Carter the digest; he should sign once.
- **The sign-off verb hashes `--dir`'s file**, so `--dir` is the lane checkout
  at the PR head, never the primary.
- **`approval policy apply` runs an amend per proposal.** Combine lines into
  one proposal page or the policy PRs conflict.
- **`approval log sync`, never `git pull`, brings the primary current**, and
  it refuses on an untracked file that main now tracks. Never copy a file
  into the primary's tracked tree; `private/` is the only safe destination.
- **Deletes use literal paths under a `mktemp -d` directory.** An unexpanded
  `$TMPDIR` in an `rm` fails closed to `files.delete.out_of_scope` and reaches
  the phone; `/Users/Shared` is never scratch.
- **The session scratchpad is shared across lanes.** Lanes use their own
  `mktemp -d` for logs, and `grep -a` on test logs (they contain bytes grep
  reads as binary).
- **A probe's tests must not write the real pointer or state files.** The Muse
  probe's suite overwrote its live pointer mid-session and redirected
  Carter's `--arm`.
- **Hook refusals seen beyond the 09-16 list:** `sleep`, `git -C <path> …`,
  `git check-ignore`, `git rebase`, `git commit --amend`, `awk`, non-read
  command substitution, and `backlog task edit` notes containing a backtick
  inside double quotes (use single quotes).
- **Attribution is honest:** Opus lanes use the trailer their own session
  specifies; the orchestrator uses its own.
- **Verification tier works:** a Sonnet pass per PR, handed the acceptance
  criteria, caught a PR with no CI on its head, two wording overclaims and a
  coverage gap. Fable reviewed the one diff that changed production
  attribution and sent it back twice, both times for a real gap.
- **When Carter runs something live, read the state yourself.** Most of the
  Muse findings came from reading the probe's recorded envelopes while he
  typed, not from the report.
