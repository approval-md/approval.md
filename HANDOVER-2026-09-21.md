## 6. Working rules learned tonight

- **One gated script per install**, and never a chain of fetches through the
  gate; documentation comes through ungated fetch.
- **Never `rm -rf` from a lane.** It is `files.delete.out_of_scope` outside the
  workspace and costs nine minutes of a sleeping human's gate.
- **Register with a sealed-delivery key** when a lane files a request it will
  spend itself, or the raw token prints in the daemon window and only the human
  can relay it.
- **The vendor installer wants its `--dir` absent.** Do not `mkdir -p` it.
- **The 25-line help cap is real and CI enforces it on shard 3**; a lane that
  runs only its own suites will not see it. Add `cli-long-help` to every lane's
  matrix when help text changes.
- **Do not edit `src/` while a full `npm test` runs**: the doctor's
  build-freshness row is inside the suite and will flag it.
- The Edit tool refuses cross-worktree writes; a lane calls `EnterWorktree` on
  its own path first. The orchestrator hands small fixes back to the lane
  rather than switching.
