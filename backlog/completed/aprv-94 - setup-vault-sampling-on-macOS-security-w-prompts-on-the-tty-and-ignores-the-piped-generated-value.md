## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Observed running examples/email-demo.md (2026-08-18): `approval setup vault` on a macOS terminal printed Apple's `password data for new item:` prompt and waited; the operator, not knowing what to type, pressed Ctrl-C and the verb died having stored nothing. Cause, reproduced under expect: `security add-generic-password -w` reads the secret from the controlling tty whenever one exists and IGNORES piped stdin, so the "attempt one" pipe in setup-common.ts store() (`input: value\\nvalue\\n`) never supplies the value on a real terminal. Whatever the human types is stored, the read-back mismatches, and only the argv fallback stores the generated value; if the human types nothing or aborts, nothing is stored. The APRV-74 review probe ("piped stdin exiting 0 while leaving no findable item") was this same behaviour seen from the other side. Fix, verified by probe: spawn security with `detached: true` so it starts a new session with no controlling tty and must read stdin; the piped value is then stored and read back exactly, with no prompt shown. Applies to every generated-value keystore store (vault passphrase, sampling secret). storePrompted() (the bot token) is unaffected: there the tty prompt is the intent.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Reproduced under expect: `printf v\\nv\\n | security add-generic-password -U -w` on a pty printed "password data for new item:" and stored what was typed on the tty, ignoring the pipe. With spawnSync detached: true (new session, no controlling tty) the same command read the pipe, showed nothing, and read-back returned the piped value. Both probes used a throwaway service name, deleted afterwards.

Change: setup-common.ts store(), attempt one now passes detached: true (widened type: the option is undocumented for spawnSync but honoured by SyncProcessRunner; if ever ignored, the read-back guard drops to the pre-existing argv path). storePrompted() untouched: the bot-token prompt on the tty is intentional there. No unit test: the runner is a real-keystore seam that tests never construct by design; verification is the demo run (AC 4).
