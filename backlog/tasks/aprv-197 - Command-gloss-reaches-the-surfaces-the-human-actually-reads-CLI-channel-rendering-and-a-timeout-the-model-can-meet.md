## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
2026-09-01, from the human, mid-wave: 'i still get a claim like summary: cp /private/tmp/... but i thought we implemented a change so that the claim would be an llm summary'. APRV-144 built the gloss correctly but two choices hide it: (1) it is attached by the Telegram LISTENER only; approval channel cli and the interactive queue walker render the raw claimed summary with no gloss and no COMPUTED command_breakdown line, and tonight's incident (APRV-196) made the CLI channel the primary deciding surface; (2) the haiku subprocess has a 2s SIGKILL timeout, while a cold claude -p start routinely exceeds 2s, so on Telegram the gloss can be chronically absent and absence is silent by design, indistinguishable from unimplemented.

Scope: (a) render the deterministic command_breakdown (already in COMPUTED) in the CLI channel and queue views, no model needed; (b) wire the same opt-in gloss into the CLI channel's interactive prompt path with the same never-load-bearing, fail-to-absence properties; (c) make the timeout honest: measure real claude -p haiku latency, raise the ceiling accordingly or pre-warm once per listener/channel process, and count gloss absences somewhere a human can see (doctor or the channel's stderr) so silent failure is at least visible failure. Constraints unchanged from APRV-144: gloss never enters payload store, hash, or log; clearly labelled model-authored; no safety judgments in the prompt; nothing branches on gloss content.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
MEASUREMENT (AC #3). Five fresh `claude -p --model haiku` spawns of gloss.ts's own GLOSS_INSTRUCTION over a compound git command, this machine, 2026-09-01: 14594ms, 10154ms, 11303ms, 13546ms, 14858ms (min 10.2s, median 13.5s, max 14.9s, all exit 0). APRV-144's ceiling was 2000ms, so EVERY call was SIGKILLed: the gloss was not intermittently absent, it was absent 100% of the time, and since absence is silent by design that is indistinguishable from the feature never having shipped — which is exactly how the human reported it. Pre-warm was the alternative and the measurement rules it out: those five runs were consecutive, so runs 2-5 were warm in every sense a separate process can be (page cache, module cache), and still took 10-15s. The wait is inference, not start-up. GLOSS_TIMEOUT_MS is therefore 20000ms: above the slowest observed run with headroom.

DESIGN. (1) attachGloss/glossMaterial/glossAbsenceLine moved out of cli/channel-telegram.ts into a new cli/gloss-attach.ts, so the listener and the terminal walker describe payloads through ONE function over the same payload views; the listener keeps a three-line withGloss wrapper so its dispatch loop diff stays small (Lane D is editing that file for APRV-196). (2) attachGloss returns an outcome — attached | absent | opaque — and 'opaque' is kept distinct from 'absent' on purpose: a payload with no structural view was never going to get a sentence, and a counter that added the two together would report a broken subprocess every time an opaque payload went by. (3) The label '(model, unverified)' is now one constant, GLOSS_UNVERIFIED_SUFFIX in channels/contract.ts, next to the field it labels; TELEGRAM_GLOSS_SUFFIX re-points at it and channels/cli.ts appends it in formatValue. Two channels rendering one field under two labels is how one of them ends up looking authoritative. (4) command_breakdown needed no new rendering code — channels/cli.ts's FIELD_ORDER already listed it — but nothing pinned it, so it is now pinned by test on the terminal surface as it already was on Telegram.

THE DEFAULT, and why the telegram test failed. Raising the ceiling to 20s exposed something the 2s ceiling had been hiding rather than preventing: the listener verb wired spawnGloss UNCONDITIONALLY, so tests/channels-telegram.test.ts's '--once' case (which spawns the real verb) had always been invoking a real `claude` — it just died in 2s. At 20s it delivered late and the test timed out. CLAUDE.md's rule is that the suite never spawns anything, so the fix is the wiring, not the test: --gloss is now an explicit OPT-IN on all three surfaces that wire a runner — `channel cli`, `channel telegram listen`, and `up` — and nothing spawns without it. This also carries out the human's decision for the CLI channel (gloss off by default, --gloss explicit); the deterministic command_breakdown always shows and costs nothing. A first draft defaulted the CLI channel to ON at a real TTY and OFF over a pipe; it is recorded here only because the reasoning is worth keeping: the flag-based default would have put a model inside npm test, and a tty-based one would have hidden a 10-15s per-request wait behind a default nobody chose.

OPEN QUESTION FOR THE HUMAN. --gloss is opt-in on every surface, including `channel telegram listen` and `up`, which is a behaviour change from APRV-144's always-wired listener. In practice nothing is lost — with the 2s ceiling that listener produced a gloss zero times — but it does mean the phone gets no model sentence until the listener is started with --gloss. If the 10-15s per request is acceptable inside a dispatch cycle (nobody is blocked at a terminal there, unlike the CLI walker), the listener's default could go back to ON while `channel cli` stays opt-in; that would need the telegram suite to stop spawning the real verb without a stub, which it currently does. Flagged rather than decided. SPEC.md was not touched: nothing here changes a documented behaviour of the gate, only two display surfaces and one flag.

DEFAULTS, DECIDED (supersedes the open question recorded earlier in these notes). The two surfaces default OPPOSITE ways, and the asymmetry is the point: on `channel telegram listen` and `up` the gloss is ON by default with `--no-gloss` to drop it, because the phone is where an approver meets a request they did not watch being made, and the 10-15s is spent inside a dispatch cycle already waiting on the network, blocking nobody; on `channel cli` it is OFF with `--gloss` to ask, because a person is sitting in front of that pause. `--gloss` is accepted on the listener too (it restates the default) so one command line works on both verbs, and `--no-gloss` wins a tie, because the flag that removes a language model from the path should never lose one. `dispatchPending` itself still defaults to NO runner, so no programmatic caller spawns a subprocess by importing it: the flag decides for the VERB only, and glossWiring is exported and unit-tested over all four flag combinations.

THE SUITE NO LONGER SPAWNS A MODEL ANYWHERE. tests/fake-claude.ts writes an executable `claude` and returns the PATH fragment that puts it first; it is used by channels-cli (three cases), by channels-telegram's '--once' child, and by EVERY spawn in up.test.ts through its cliEnv — that last one matters beyond this task, since `up` starts the listener and without it every `up` case would now call a real model. PATH is the only seam available on purpose: cli/gloss.ts spawns a fixed binary with no shell, because a runtime that let a policy or an env var name the executable it runs would have invented a new way to be told what to execute. The '--once' test now also ASSERTS the stub's sentence reaches the prompt labelled '(model, unverified)' — the one place in the suite that proves the verb is wired to a runner at all, since every other gloss test injects one.

THE FLIP'S BLAST RADIUS, and what it cost to find. Turning the listener's gloss ON by default broke five END-TO-END suites on the first full run — not because the gloss is wrong, but because they spawn the real listener verb and therefore started invoking a real `claude` at ~13s per request: e2e-demo, e2e-mcp-demo, e2e-email-demo (the M7 chain, steps f through j, plus the setup path) and up.test.ts's composed-runtime case. Every one of them now takes the fake binary through its own cliEnv, which is the same seam the telegram and cli suites use. Worth stating plainly, because it is the real lesson of this task: a default that spawns a subprocess is a dependency EVERY spawning test inherits silently, and the only reason APRV-144's version looked harmless is that its 2s ceiling killed the child before anyone noticed the cost.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Both reading aids now reach the surfaces a human reads. The classifier's command_breakdown renders on the terminal (deterministic, free, [computed] (classifier), always on), and the model gloss renders in the CLAIMED block labelled '(model, unverified)' from one constant shared with Telegram, attached by one shared module (cli/gloss-attach.ts) that both channels call. The 2s timeout that made the gloss absent 100% of the time is now a measured 20s (five haiku spawns: 10.2-14.9s; the same measurement rules out a pre-warm, since consecutive warm runs cost the same), and absences are counted and reported on stderr by the walker and by each dispatch cycle, so a broken subprocess reads as broken rather than as unbuilt. Defaults are deliberately asymmetric: ON for `channel telegram listen` and `up` (--no-gloss to drop it), OFF for `channel cli` (--gloss to ask), because only the terminal has a person waiting in front of the pause. Verified by 11 new tests plus tests/fake-claude.ts, a shared fake binary on PATH now used by the cli, telegram, up and all four e2e demo suites so the suite spawns no model anywhere: rendering of both aids, all four no-answer paths, the opaque path, the end-to-end verb for success and failure, the flag matrix, and the never-load-bearing re-assertions (payload hash and rendering unchanged, nothing in events.jsonl after a real grant, two adversarial sentences changing nothing but their own line). npm test 2510/2510, lint and build clean.
