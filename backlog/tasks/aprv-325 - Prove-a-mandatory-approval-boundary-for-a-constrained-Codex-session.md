AC1, the boundary report, part 1. Codex version: 0.152.1 exactly, pinned as a const in schema/codex-instance.schema.json and re-declared in src/codex/manifest.ts, so a manifest naming any other version is refused. Platform: darwin only, also a const. The TOOL boundary is one MCP tool, codex_workspace_apply, served by approval codex serve from src/codex/serve.ts, whose catalog is a literal of length one checked at call time as well as at list time. The EXECUTION boundary is the Seatbelt-confined child of approval codex start: a disposable workspace is its only writable path, the canonical workspace and the gate home are read-only, credential files beside the log are unreadable, outbound network including loopback is denied, and descendants inherit all of it.

AC1, part 2. Trusted components: the root-owned install root and everything under it, which is the manifest, the pinned Node, the CLI, the broker and the strict server; the attested APPROVAL.md; and the hash-chained log, read only after chain verification. Residual direct capabilities, stated as capabilities rather than as gaps: a confined shell may READ whatever the host user can read, because read scoping is Lane 3's allowRead profile and had not landed on origin/main when this was written; a confined shell may write freely inside its own disposable workspace, which is the point of giving it one; inbound sockets are not denied; and the environment allow-list is a control over names, best-effort by construction, with egress denial as the load-bearing control beside it.

Limits of the desktop session. A Codex desktop application a person starts outside the confined room is not in it, and nothing here constrains its native write, patch, browser or plugin surfaces.

The native hook cannot substitute for it, and APRV-311 established why. Native v6 omits the per-call execution directory, so a relative target can name a protected gate organ while classification sees an ordinary session-root file.

Every native shell pre-tool event is therefore refused before any gate state is touched. Everyday native activation stays blocked until a Codex release exposes the effective per-call directory and a success or failure contract, which is APRV-311's remaining scope.

AC2 continued, from APRV-325.3, tests/codex-confine.test.ts, 21 cases. Every confinement case is a PAIR: the same script unconfined, where it MUST succeed, and confined, where it must fail. Denial of a canonical workspace write, of a gate log and policy write, and of a credential read each carry their control leg. The egress case compares ECONNREFUSED unconfined against EPERM confined, because a closed port fails either way and the two codes are what separate a denial from an absence. Timeout: a spinning child killed at the deadline leaves no canonical effect. Disconnect is recorded honestly rather than claimed: for this arrangement it reduces to one of two already-proven cases, since a transport that drops before the broker starts produces no filesystem effect at all, and a process that dies mid-transaction is the crash case above, which records an indeterminate outcome and retains the journal. No separate disconnect probe was run and none is claimed.

AC3, the executor. The broker reads APPROVAL.md ONCE, hashes those exact bytes, and checks them against the latest attestation over records that have passed chain verification; an unattested, drifted or unparseable policy refuses before a plan exists. Authorization is the real runtime's: core/gate.ts register and request, core/execute.ts startExecution and its outcome verbs. There is no model judgment anywhere on the path and no native approval impersonation: the broker mints no grant, fabricates no token, and a manual class refuses with approval-required naming the action keys a person must decide. A token, when there is one, is verified where it always was, against the log's digest.

Protected configuration remains outside agent control. The acting identity, workspace root, policy path and log path come from the instance manifest under a root-owned install root, and parseBrokerInput refuses an unknown key rather than ignoring it, so a caller that names an actor, a root, a class, a token or a sandbox posture is told no instead of being quietly overridden. The strict server publishes no identity, path, class or token argument at all. Nothing in APRV-325.2 or APRV-325.3 writes to .approval or to APPROVAL.md, and the confined session cannot write either of them.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
The boundary is real, bounded, and written down. A constrained Codex session reaches the canonical workspace through exactly one MCP tool, served by a strict one-tool server separate from the broad verb catalogue, and the change it carries is planned, classified per path, authorized through the real gate, started on every leg before any byte moves, then staged, journaled and applied under a workspace lock, with the outcome taken from reading the workspace back. A shell this runtime starts gets a disposable workspace that is its only writable path, no gate write authority, no ambient credentials, no readable credential files, no egress, and no opt-out, and its descendants inherit all of it. Codex 0.152.1 on darwin, pinned as a const. Proven by isolated probes with observed effects and exit codes across three subtasks, and delivered in PRs 366, 380, 406 and 413. What is NOT claimed is stated as plainly: read scoping is absent pending Lane 3, a desktop application started outside the room is unconstrained and the native hook cannot substitute because the per-call directory is missing upstream, and the live Telegram pair is Carter's and has not happened. Nobody should call an installation a mandatory boundary on this evidence.
